Paste the token @BotFather gave you. The page asks Telegram who the bot is, and lists the chats that wrote to it lately, with their chat ids. Those ids are what a route in Angelia needs.

Your token stays in this browser. The page sends it only to api.telegram.org, which is how every Telegram bot talks to Telegram. There is no server of ours in between, no analytics on this page, and nothing is stored: reload the page and the token is gone. The page's security policy lets it connect to api.telegram.org and nowhere else.

From @BotFather: digits, a colon, then about 35 letters, digits, - and _.

Stop Angelia, or any other program that uses this token, first. Telegram gives a bot's updates to one reader at a time. With two readers, one of them fails with 409 Conflict.

What the check does

  1. getMe: is the token valid, and which bot is it. A wrong or revoked token answers 401 Unauthorized.
  2. getWebhookInfo: does the bot send its updates to a webhook.
  3. getUpdates: the updates Telegram holds for the bot, up to 100. The page reads each update's chat. It sends no offset, so it marks nothing as read; another program still gets the same updates.

All three only read. The page changes nothing on the bot.

Find a chat id

  • Your direct chat: open the bot in Telegram, press Start or send any message, then press Check. A direct chat's id is your own user id, a positive number.
  • A group: add the bot to the group and send a message that mentions it, such as @your_bot hello. With privacy mode on (the default), a bot sees only commands, replies to it and mentions. A group's id is negative; most start with -100.
  • Nothing shows: Telegram keeps updates for at most 24 hours, and only until a program that polls the bot takes them.

When getUpdates fails

Telegram gives a bot's updates to one reader at a time. getUpdates answers 409 Conflict in two cases.

  • The bot has a webhook. Telegram pushes the updates to that address instead, and says: Conflict: can't use getUpdates method while webhook is active; use deleteWebhook to delete the webhook first. The page sees the webhook in step 2 and stops there. Angelia polls: when it starts, it removes the webhook first, so a service that gets this bot's updates by webhook stops getting them. Give Angelia a bot of its own.
  • Another program is polling. Angelia itself is one: while it runs with this token, it holds an open getUpdates request. A second reader makes one of the two fail with Conflict: terminated by other getUpdates request; make sure that only one bot instance is running. If this page gets it, Angelia is reading the bot, and it has already taken the updates. Angelia retries by itself after a short pause, and angelia status may show telegram: conflict for a moment.

With Angelia running, you do not need this page to find a chat id. A chat that is not in routing.yaml yet gets no answer, and the daemon log gets one line with its chat id.

Use the ids with Angelia

Angelia routes each Telegram chat to a coding agent CLI on your Mac. angelia init pairs your first chat for you. To add a chat by hand, put a route in ~/.angelia/workspace/routing.yaml:

routes:
  - { platform: telegram, chat: 111111111,      profile: coding }
  - { platform: telegram, chat: -1001234567890, profile: house, owners: [111111111] }

telegram: { token_env: TELEGRAM_BOT_TOKEN }

The token goes in ~/.angelia/env as TELEGRAM_BOT_TOKEN=…, never in the table. In a group, owners lists the user ids that may talk to the agent and approve what it runs. Then run angelia check-config.
